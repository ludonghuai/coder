# Git 自动拉取与系统代理（ide-git）需求

> 板块：IDE 的 Git 面（`lib/ide/git/**` + `packages/bao_remote` 的 git 执行）· 范围仓：baocode。
> 状态：需求（用户 2026-10-19 02:01 提出）· 已实现（2026-10-19；待真机走查）· 批 13 增量（获取 = 真拉取 / `↓N` 位置）待实现。
> 来源：用户逐字「要把autofetch入池子；并且现在仓库有更新它就不拉了，不显示远端有提交，我需要这个功能，自动拉代码远端提交的功能，系统代理和功能缺口你要给我做的完好完美稳定」。

## 1. 模块目标

BaoCode 的 Git 面在远端出现新提交时**自动发现并安全拉入**；git 子进程**自动跟随系统代理**；多仓工作区一次覆盖。用户不再需要手动 Fetch / Pull 才能看到对方的提交。

## 2. 功能点

1. **autofetch**：设置项（`git.autofetch`，默认开）+ 周期（默认 3 分钟，可调）+ 回到前台时补一次；对工作区**所有仓库**生效；结果 = 分支栏 `↓N` + 源控 / Graph 里的对方提交记录更新。
2. **安全 auto-pull**：仅当 ① 工作树干净（无未提交改动）② 可快进（无分叉）③ 本次远端改动的文件与未保存的编辑器缓冲**不相交**时，才把远端新提交拉入工作树；否则**该仓本轮不拉**（提示相交的文件名），分支栏**持续显示 `↓N` 远端提交数**；保存 / 关闭那些文件后下一周期自动拉；其余仓库照常。是否自动拉 = 设置项（`git.autoPull`，默认开）。
3. **系统代理自动继承**：git 子进程自动使用 Windows 系统代理（WinINET），无需用户手配 `git config http.proxy`；代理变更后重启 app 生效。覆盖复用既有 Settings→Network 的 `http.proxyMode` / `http.proxy`（已有 UI，不新增设置项）。
4. **多仓工作区**：`repos` 这类工作区，autofetch / auto-pull 覆盖其所有仓库；单仓失败不影响其它仓。
5. **错误可见**：**认证 / 冲突等需要用户动作的失败**在通知中心可见；**网络类失败不打扰**（后台按周期重试，恢复即成功）；分支栏显示「上次成功时间」。
6. **不打断**：autofetch / auto-pull 不抢焦点、不弹模态；auto-pull 只在本轮无脏缓冲相交时发生，拉入后已打开文件按既有 reload 语义刷新。
7. **获取按钮 = 真拉取**（用户 2026-10-19 03:31）：仓库头的「获取」= fetch + merge 的真 `git pull`（分叉时允许产生合并提交）；本地改动会被覆盖 / 合并冲突 ⇒ **拉取失败**：界面给出原因，工作树回滚到拉取前（不留 `MERGE_HEAD`、不留冲突标记）；多仓单仓失败不影响其它仓。
8. **获取按钮内的计数**（用户 2026-10-19 03:22，20:33 改口）：**多仓仓库头**的远端提交数显示在「获取」按钮**内**（图标与数字同一按钮、同一点击区；用户 20:33 原话「把数字直接放进那个按键里面」），分支标签后不再重复显示同一信息；窄宽时徽标回落到分支名右侧。单仓视图无仓库头时沿用状态栏既有 `↓N`。

## 3. 边界

- 不自动提交、不自动推送、不自动解决冲突（冲突 ⇒ 停下提示）。
- 不做 submodule 递归更新；不处理 force-push 的历史改写（只按正常 fetch 的「快进 / 分叉」判定）。
- 代理只覆盖 git 子进程；不动其它网络面。
- 不自动 rebase / 不改写历史。
- **自动轮不合并**：获取按钮的真拉取（允许 merge）不改变自动轮的 A 口径——脏树整仓不拉、只 `--ff-only` 快进、`↓N` 常显。

## 4. 验收（可机检 / 走查）

1. 远端有新提交、本地干净、可快进 ⇒ 3 分钟内（或前台恢复时）分支栏出现 `↓N`，且**自动拉入**后 `N` 归零、工作树文件更新。
2. 本地有未提交改动 或 已分叉 ⇒ **不自动拉**，分支栏**显示 `↓N` 远端提交数**（一眼可见有提交）。
3. 本次远端改动与打开文件的未保存缓冲相交 ⇒ **该仓本轮不拉**，提示相交文件名；保存 / 关闭后下一周期自动拉；其余仓库照常。
4. 系统代理开（`127.0.0.1:7890`）而 `~/.gitconfig` 无 `http.proxy` ⇒ 手动 Fetch 与自动 fetch 都能通（子进程继承系统代理）。
5. 多仓工作区：任一仓有新提交 ⇒ 该仓自动处理；一仓失败，其它仓不受影响。
6. 网络断开 ⇒ **不通知**；恢复后下一周期自动 fetch / pull 成功。
7. 设置项三个（autofetch / autoPull / autofetchPeriod）都有 UI（配置项必须有 UI），关掉即完全停止。
8. 干净 + 可快进 ⇒ 点「获取」代码拉下、`N` 归零；本地修改与远端改动相交 ⇒ 失败提示 + 工作树无 `MERGE_HEAD` / 冲突标记；本地提交与远端提交分叉 ⇒ 合并提交成功；**多仓仓库头**的 `↓N` 数字位于获取按钮**内**、分支标签后无重复（窄宽回落分支名后；单仓沿用状态栏）。
