### 2.4 冲突处置（机制设计）

#### 冲突 ① `lib/chat/panels/activity_strip.dart`

**处置**：结构取上游（`Stack` + `_sash()` + `_tree` / `_treeHeight` / `_treeRows` / `_maxTreeHeight()`），`_FilesHeader` 调用里加回 `undoTooltip: widget.undoTooltip`，其余参数随上游。

**为什么不能整段取上游**：自有面是「回合在飞时 Undo 灰显并给出原因」。它经一条参数链活着：

- `ActivityStrip.undoTooltip`（自有字段，构造参数 `this.undoTooltip`）
- → `_FilesHeader(undoTooltip: widget.undoTooltip)`
- → `_FilesHeader.undoTooltip` → `PanelButton(tooltip: undoTooltip, onTap: onUndo)`
- 显示门：`if (onUndo != null || undoTooltip != null)` —— 回合在飞时 `onUndo` 为 null，靠 `undoTooltip` 非空才让按钮出现并灰显。

冲突块里上游那一侧 `build` 的 `_FilesHeader(...)` 调用只传 `onUndo` / `onKeep`，没有 `undoTooltip:`。整段取上游 ⇒ `undoTooltip` 恒为 null ⇒ 回合在飞时 `onUndo == null && undoTooltip == null` ⇒ **Undo 按钮直接不出现**，灰显与原因一起消失。这是静默丢功能，不是样式差异。

**依据** `lib/chat/panels/activity_strip.dart`「Why Undo shows greyed out instead: with [onUndo] null it still shows」（该档 `undoTooltip` 字段的文档注释首行，冲突区外已合入；次行续「(§9: a turn still running).」）

**上游那侧的其余改动一律接收**：sash 拖高、`ChangeTree(height:)`、`key: _tree`、`_countTreeRows()`、`_sash()` 的 `ValueKey('activity-strip-sash')` —— 这些是上游本批的布局骨架，与自有参数正交。

#### 冲突 ② `test/composer_test.dart`

**处置**：取上游的 `inset = chatGutter(list.width)`，共三处断言；本地那句「24 down」的注释随之改写。

**为什么取上游不丢自有语义**：自有那一侧把值写死成 `list.top + 24`；上游改成读函数 `chatGutter(list.width)`。这个函数就在本仓合并后的档里：

**依据** `lib/chat/chat_history_view.dart`「double chatGutter(double width) => width < 600 ? 16 : 24;」

测试里 `list.width` 来自 800 物理像素、`devicePixelRatio = 1` 的默认视口 ⇒ `chatGutter` 返回 24 ⇒ 上游写法的期望值与原来的字面量**在这个宽度上等同**，而 `24` 从此不再是一份手抄的副本。

**这条字面量本来就不该留**：它读的是本仓 gutter 函数的值，函数一变（或测试视口一变）断言就假红/假绿，而断言想说的是「粘顶副本贴住列表顶部内侧」。取上游即把「我们抄下的那个数」换成「函数自己算的数」，语义更强。

**核对结论**：`test/composer_test.dart` 在 `docs/design/fork-deltas.md` 第 3 节登记的是「T61 自有用例 + 四条自有 import + btest 四处期望调整」，不含这个 `24` ⇒ 取上游不动登记面。
